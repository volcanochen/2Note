# MD2OneNote 开发探索历史

> 记录从「OneNote 粘贴缩进丢失」到「自定义 COM 加载项」的完整探索过程，含每一步的坑与教训。
> 时间线：2026-11-04 ~ 2026-11-06。

## 第 0 阶段：问题诊断（11-04）

**问题**：AI 对话里复制的内容粘贴进 OneNote 后，多级列表缩进全部丢失、变成平铺段落。

**假设求证**（对照测试页 `onenote-paste-test.html`）：
1. 复制源的 HTML 没有真嵌套结构，缩进靠 CSS padding-left 模拟 ✓
2. OneNote 粘贴只认「真嵌套 `<ul>` + 内联样式」，丢弃 `<style>`/class ✓

## 第 1 阶段：剪贴板往返方案（md2onenote.bat，11-04）❌

思路：剪贴板 Markdown → 转成真嵌套+内联样式的 CF_HTML → 写回剪贴板 → 用户 Ctrl+V。

- 交付 `md2onenote.ps1 + .bat`，验证了 2/4 空格缩进归一化、ol/ul 混合、粗体/链接/行内代码、标题、复选框。
- **坑 1**：PS1 必须 UTF-8 带 BOM，否则 PS5.1 中文乱码。
- **坑 2**：`DataObject.SetData('HTML Format', 字符串)` 底层按 UTF-16 写入，与 CF_HTML 要求的 UTF-8 字节流+Fragment 偏移不符 → 用户实测贴出乱码。改用 P/Invoke（GlobalAlloc GMEM_MOVEABLE → Marshal.Copy UTF-8 → SetClipboardData）。
- **坑 3**：PS 里 Marshal 必须写全名 `[System.Runtime.InteropServices.Marshal]`；出错后仍弹「完成」误导用户 → 加 Stop 策略+返回值检查。
- **结局**：方案逻辑正确，但用户粘贴仍丢缩进——**因为 OneNote 的 HTML 导入器会压平嵌套**，这条路注定不通。

## 第 2 阶段：OneMore 对照实验（11-04）❌（定位关键）

- 安装开源 OneMore 8.0.0（msi 静默装经沙箱报 2343/1619，用户手动装成功）。
- 实测其 Convert Markdown 同样压平嵌套——**证实根因在 OneNote 导入器，而非剪贴板格式**。
- 附加发现：OneMore 连点「粘贴富文本」会触发 OpenClipboard 抢锁异常而自杀退出。
- **结论**：必须生成 OneNote **原生 XML** 经 `UpdatePageContent` 写入。OneMore 的 `Models/Bullet.cs` 提供了原生 XML 结构参照。

## 第 3 阶段：PowerShell 原生 XML 方案 v3/v4（11-05 上午）✅ 技术验证

交付 `md2onexml.ps1 v3`（+vbs 隐藏启动器+桌面快捷键）：
- 剪贴板**优先解析 HTML Format**（关键认知：聊天窗口「复制」给的是渲染后富文本，不是 markdown 源码）；无嵌套时按 padding-left 自适应推导层级；h1-h6/b/i/code/a/checkbox/pre 全支持；markdown 纯文本兜底。
- 插入 = 新建独立 Outline 放在光标容器下方，多次插入用 push-down 循环防重叠。
- **E2E 全绿**：8 items 全解析、嵌套正确、编号正确。
- **坑**：①COM 窗口对象跨进程复用 0x80042005；②one:Size 必须带 height；③自造 CF_HTML 别双层包 html/body（EndFragment 偏移截断）；④中文验证的「失败」是误报——OneNote 按字体 run 把中英文拆成多个 span，需按 one:T 拼接后验证。

## 第 4 阶段：COM 加载项 v1（11-05）⚡ 加载即崩

用 C# 把 v4 引擎 1:1 移植成 OneNote COM 加载项（`MD2OneNote.Addin.dll`）：IDTExtensibility2 + IRibbonExtensibility + RegisterHotKey。

**现象**：OneNote 加载时弹「运行时错误」，LoadBehavior 3→2。

**排障波折（两条弯路 + 一次顿悟）**：
1. 误修 ①：怀疑类型库残缺——修了 `TypeLib {0EA692EE}`（补 win32/win64）确实必要但不充分。
2. 误修 ②：怀疑接口方法顺序——被 ksaddndr.dll 类型库 vtable + OneMore 声明双重证伪后回退。
3. 期间发现并修复**毒注册**：WPS 写入的 HKCU TypeLib `{A537E638}` 路径双反斜杠损坏；HKLM 正版 `{AC0714F2}` win32/win64 路径为空——用 ksaddndr.dll 正确路径重建（备份在 poison-backup）。
4. **真正根因**：接口参数缺 `MarshalAs`。x64 上 CLR 把 `object` 参数编组为 24 字节 VARIANT，而真实 IDTExtensibility2 传裸 IDispatch*（8 字节）→ 桩错位读栈 → AV/异常。照 OneMore 加 `[In, MarshalAs(UnmanagedType.IDispatch)]` 后，真实参数测试 hr=0、方法体执行。
- **测试方法学教训**：注册表 Assembly= 必须与 DLL 文件名一致，否则 mscoree 回退旧 DLL（Tiny 测试首测无效的原因）；DLL 被残留代理锁定时 Copy-Item 会静默失败。

## 第 5 阶段：加载成功但菜单不出现 + 绑定失败（11-05 下午）

- 用户反馈「加载成功但没看到右键菜单」。GetCustomUI 已被调用 → 头号嫌疑=空 `<tabs/>` 导致整个 customUI 被拒。
- `_app` 绑定失败取证：PIA IApplication cast 进程内 QI `{A47D3223}` → **E_NOINTERFACE**（宿主对象是纯 dispinterface，真实 IID `{452AC71A}`）。
- 决定性探针：GetTypeInfo(0,0) 的 ITypeInfo::Invoke = E_NOTIMPL；FUNCDESC 解析证实 GetHierarchy 4 参、cParamsOpt=0。
- **方法论转折**：意识到 out-of-proc 探针结论不能外推到真实环境 → 停止外部探针，把多策略调用器（raw + ITypeInfo 回退 + 全链路日志）直接装进插件，用真实环境验证。
- 重构：OnConnection 存原始 object；GetCustomUI 改 OneMore 式（onLoad + 真实 tab + contextMenus）；OneNoteApp 全改晚绑定；**PIA 引用彻底移除**。

## 第 6 阶段：堆损坏崩溃（11-05 晚）💥 最隐蔽的一战

- 重启后 MD2 选项卡出现（菜单 XML 修复生效）✓，但点粘贴卡几秒无结果。
- 日志链路全通到 GetPageContent（[out] 写回成功），随后戛然而止。
- **Windows 事件日志**：DllHost.exe 崩溃 0xc0000374（堆损坏），时间吻合——顺带揭示插件运行在 **DllHost COM 代理**这一架构事实。
- **根因**：VT_BYREF|VT_BSTR out 参数所有权——跨进程时 oleaut 代理写回可能先 SysFreeString 调用方原始 BSTR，而我们预登记了它并在 finally 再 free → double free。GetPageContent 是第一个带 out 的调用，只有它崩。
- **修复**：每个 out 槽只释放最终指针一次；入参 VARIANT 加 CleanupVariant 防泄漏。
- **重要结论**：晚绑定 raw IDispatch 在代理进程内完全可用（GetIDsOfNames/Invoke/[out] 写回全 OK），PIA 路线彻底不需要。

## 第 7 阶段：格式丢失（11-05 深夜）🔍 一行签名定乾坤

- 用户报「粘贴成功但没格式」。日志：`htmlFmt=0` 但格式枚举显示剪贴板上明明有 **HTML Format**（Chromium 来源）。
- 加分步日志：`handle ok, size=0`——句柄有效但 GlobalSize 得 0。
- **根因**：`GlobalSize` 真实签名是 `SIZE_T GlobalSize(HGLOBAL)`（返回值），误声明为 out 参数 → 永远 0 → HTML 数据被当空。CF_UNICODETEXT 不受影响（走 PtrToStringUni）。
- 修复后用户确认「可以了终于可以了」：HTML 20247 字节 → parsed html 14 items → update OK 全链路绿。

## 第 8 阶段：自定义热键（11-05 深夜→11-06）

- 用户 Ctrl+Alt+M 被其他应用占用，要求可配置。
- 实现 `HotkeyConfig`（hotkey.txt 解析器）+ `set-hotkey.ps1`（含 RegisterHotKey 占用检测）。
- 用户选定 **Ctrl+Shift+V** 并保存。
- 坑：旧版 csc 不支持 C#7 内联 out 声明；PS5.1 不支持整数字面量 `u` 后缀。

## 沉淀的核心教训

1. **不猜，取证**：每个「根因」都要有可复现证据（日志/事件/探针），本历程里两次「合理推断」都被证据推翻（接口顺序、PIA 唯一可靠论）。
2. **环境隔离决定结论效力**：out-of-proc 探针结论不能外推到 in-proc/代理环境，反之亦然。
3. **Windows/COM 三大隐形雷**：参数级 MarshalAs（x64 VARIANT 槽位）、跨进程 [out] BSTR 所有权、P/Invoke 返回值 vs out 参数——三个都是「能跑但不对」或「必崩但不留痕迹」的类型。
4. **留日志就是留退路**：插件内置的全链路日志是所有疑难杂症的最终破案工具。
5. **OneNote 生态事实**：HTML 导入器压平嵌套是所有「转 HTML」方案的死穴；OneMore 的 XML 结构与 customUI 形态是可靠的参照系。
